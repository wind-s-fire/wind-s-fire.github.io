虚拟内存

发表于2026-11-10|更新于2026-11-10|pwn
|浏览量:

定义

虚拟内存是一套由操作系统软件和硬件内存管理单元协同实现的、综合性的内存管理技术体系。它的核心目标是：

1·提供虚拟地址空间的抽象（让每个进程有独立的、连续的大空间）。【虚拟地址空间另有文章，本文不作解释】

2·高效、安全地管理有限的物理内存资源。

3·实现内存的共享与保护。

核心机制

VMA（Virtual Memory Area，虚拟内存区域）是内核在每个进程的 mm_struct 中维护的数据结构。它的职责是划定虚拟地址的用途和规则。

一个 VMA 节点记录的信息大致如下：

就像作土地规划：城市的土地规划局把一块地划为”住宅用地”（VMA），规定了这块地可以盖住宅，但不能盖化工厂（权限）。至于这块地上的房子实际上盖了没有、盖了几栋——那是另一回事。

VMA 层面，”映射”只意味着一件事：一段连续的虚拟地址区间已经被声明用途了。它不涉及任何物理内存的分配。

VMA 的来源

进程中的 VMA 主要来自以下几个途径：

来源 典型 VMA 何时建立
ELF 加载 .text 段、.rodata 段、.data 段、.bss 段的 VMA execve() 系统调用内部
动态链接器 共享库（libc.so 等）的代码段和数据段 ld.so 在 main 之前映射
堆扩展（brk） 堆 VMA 扩大 首次 malloc 时 ptmalloc 调用 brk()
mmap 调用 文件映射、匿名映射、共享内存的 VMA 用户显式调用或 malloc 大块分配间接调用
栈自动增长 栈 VMA 扩大 缺页异常处理程序发现栈需要扩展时

参数释义

/proc//maps 每行格式

地址范围 权限 偏移量 设备号 inode 路径
00400000-00401000 r-xp 00000000 08:01 123456 /bin/cat
字段一：地址范围

这是该 VMA 在进程虚拟地址空间中占据的起始地址和结束地址（结束地址不含在内，即 [start, end)）。

00400000-00401000 表示这段 VMA 覆盖的虚拟地址从 0x00400000 到 0x00401000（不含），总共 0x1000 = 4096 字节 = 恰好 1 页（4KB）。

为什么地址是这些值？

x86-64 Linux 下，可执行文件的默认加载基址是 0x00400000（可通过 ld 的 -Ttext 修改）。链接器在生成 ELF 文件时，将 .text 段的虚拟地址硬编码为从 0x00400000 开始。内核加载时原样使用这些地址（除非启用了 PIE——位置无关可执行文件，则基址会加上 ASLR 随机偏移，通常落在 0x55... 或 0x7F... 范围；这里 0x00400000 说明 /bin/cat 是非 PIE 的传统可执行文件；PIE内容在其他文章）。

字段二：权限

四个字符，分别表示：

字符位置 含义 取值
第 1 位 read 可读 r = 可读，- = 不可读
第 2 位 write 可写 w = 可写，- = 不可写
第 3 位 execute 可执行 x = 可执行，- = 不可执行
第 4 位 共享/私有 p = private 私有，s = shared 共享

r-xp 解读：可读、不可写、可执行、私有映射。这正是 .text 段的经典权限组合——CPU 必须能读取指令（r）、执行指令（x），但绝不允许程序在运行时修改自身代码（没有 w）。p 表示修改只对本进程可见（COW 机制）。

rw-p（data 段、bss 段、堆、栈）：可读可写，不可执行，私有。NX 位阻止了在这些数据区域执行代码。

r--p（rodata 段）：可读，不可写，不可执行，私有。比 data 段更严格，连写都不允许。

字段三：偏移量

对于文件映射，这是该 VMA 在映射文件中对应的起始字节偏移。它不是虚拟地址，不是物理地址，而是文件内部的逻辑偏移量。

以 /bin/cat 的三段为例：

匿名映射的偏移量：bss 段（00403000-00404000 rw-p 00000000 00:00 0）的偏移量为 0，因为 bss 没有对应的文件内容——它不是从 ELF 文件映射的，而是匿名映射补齐的。堆和栈同理，偏移量始终为 0 且无实际意义。

字段四：设备号

主设备号:次设备号，标识映射文件所在的块设备。08:01 表示主设备号 8、次设备号 1。

在 Linux 中，主设备号 8 通常对应 SCSI/SATA 磁盘（sd* 设备）。08:01 指向 /dev/sda1——即第一块 SCSI/SATA 磁盘的第一个分区。

对于匿名映射（bss、堆、栈），设备号为 00:00——表示没有关联任何设备，这是一个纯内存区域。

字段五：inode

映射文件在文件系统中的 inode 编号。inode 是文件系统中每个文件的唯一标识符——它不是文件名，而是文件在磁盘上的”身份证号”。

同一个文件可以通过 stat 命令查看 inode：

对于匿名映射，inode 为 0——因为根本没有文件，自然也就没有 inode。

设备号 + inode 组合可以唯一标识系统中的任何一个文件。内核用这对值来判断：两个不同进程映射的”同一个文件”是否真的是同一个文件（而不是恰好同名）。如果设备号和 inode 都匹配，可以安全地共享物理页（COW）。

字段六：路径

被映射的文件路径，或特殊标记。

文件路径：直接显示映射的源文件。对于 ELF 可执行文件和共享库，它是磁盘上的绝对路径。对于使用 mmap 显式映射的任意文件，同样显示其路径。

特殊标记（放在方括号中）：

标记 含义
[heap] 堆 VMA——由 brk/sbrk 管理的动态内存区域
[stack] 主线程的栈 VMA
[stack:] 某个线程的栈（tid 为线程 ID）
[vdso] vDSO（virtual Dynamic Shared Object）——内核注入到每个进程的虚拟共享库，提供 gettimeofday 等高频系统调用的用户态快速路径
[vvar] vDSO 配套的只读数据页，内核用来与 vDSO 代码共享时间等数据
[vsyscall] 老式 vsyscall 页（已被 vDSO 取代，仅保留兼容）
[anon:] 通过 memfd_create 或 prctl(PR_SET_VMA, PR_SET_VMA_ANON_NAME) 命名的匿名映射
[anon:...] 或无标记 普通的匿名映射（malloc 大块、mmap(MAP_ANONYMOUS) 等），路径列为空

注意：bss 段（00403000-00404000 rw-p 00000000 00:00 0）路径为空——它不是 [heap] 也不是 [stack]，而是一个紧贴在 data 段之后的匿名映射。内核没有给它特殊标签，只靠地址范围紧接 data 段来体现它的身份。

虚拟地址空间

定义

一个虚假的地址存放空间，用于实现内存隔离和虚拟内存管理，大小由系统位数决定，如32位系统虚拟地址空间为4GB，64位系统为256TB（假设地址空间为N位，则地址范围为0~2^(n-1)）。

不同于物理地址空间，物理地址空间是实际物理内存的地址集合，其中的每个地址都指向具体的存储单元，而虚拟地址空间中的地址可能未分配、指向磁盘或已映射到物理内存。

进程的虚拟地址空间

每个进程在操作系统中都有独立的虚拟地址空间，使得进程认为自己独占内存，这就像给每个进程都发了一张专属的、完整的地图，它们都以为自己是这片“土地”的唯一主人，但实际上，操作系统和硬件在背后将这些不同的“地图”动态地翻译到同一片物理内存“实地”上。

划分

典型的虚拟地址空间划分包括：

高地址部分（内核空间）：

​ 内核区：操作系统核心代码和数据，所有进程共享，但用户态程序无权访问。

低地址部分（用户空间）：

​ 代码区和数据区（text、data、bss）：存放可执行文件的指令和静态数据；

​ 堆区：动态分配内存区域，随着malloc等操作向高地址扩展；

​ 共享库映射区：系统库在物理内存中只存储一份，多个进程共享；

​ 栈区：用于函数调用和局部变量存储；

​ 其他区域；

目的

1·核心目的：隔离与保护

如果没有隔离，一个进程的指针错误（如野指针）可能会意外地写入或读取另一个进程的数据，导致程序崩溃或数据泄露；恶意程序可以轻易地窃取或破坏其他进程（如银行软件、通讯软件）的敏感信息；一个进程的崩溃可能导致整个系统或其他进程的不稳定。

通过各自独立的页表映射，它们最终会指向完全不同的物理内存位置，或者其中一个地址可能是无效的。虚拟地址空间像进程的“楚门的世界”，在不同的地方，互不可见，互不影响，都以为自己占有全世界。

2·简化编程

对于程序员来说，每个进程都从相同的起始地址（例如0x0或0x400000）开始加载代码，拥有连续的堆栈和堆空间。他们无需关心物理内存的实际布局、其他进程占用了哪些内存，或者内存是否足够。虚拟内存系统提供了这种内存抽象，极大地简化了应用程序的开发。

实现机制：页表

每个进程都有一个专属的页表，由操作系统在创建进程时建立，并存储在物理内存中。CPU中有一个特殊的寄存器（在x86上是CR3，在ARM上是TTBR0等），它指向当前正在运行的进程的页表物理地址。

  • 上下文切换：当操作系统调度器从进程A切换到进程B时，一个关键步骤就是将CR3寄存器的值从进程A的页表地址，改为进程B的页表地址。
  • 地址翻译：切换后，CPU发出的所有虚拟地址都会通过B进程的页表进行翻译。因此，即使虚拟地址数值相同，经过不同的页表翻译，得到的物理地址也完全不同。

（页表部分的详解见《页的概念》）

虚拟地址空间共享区域

内核空间共享

在大多数操作系统的内存布局中（如Linux的3:1或4:4分划），每个进程的虚拟地址空间的高端部分（例如，在32位系统上最高的1GB）被映射到操作系统内核的代码和数据。

为什么共享？ 内核需要管理所有进程，响应系统调用、中断和异常。如果内核空间不共享，每次进程切换到内核态时，都需要切换地址空间，效率极低。共享内核空间使得进入内核态（如执行系统调用）时，地址空间无需切换，访问内核数据结构非常高效。

如何保护？ 这部分内存的页表项被标记为特权级访问（如Ring 0）。用户态进程（Ring 3）无法访问这些页面，一旦尝试就会触发保护异常。因此，逻辑上它映射在每个进程的地址空间里，但物理上它是同一份内核代码，并且受到硬件保护。

显式内存共享

进程间有时需要高效地通信或共享数据。操作系统提供了显式创建共享内存区域的机制：

共享内存（数据）：两个或多个进程可以通过系统调用（如shmget/shmat）约定，将各自虚拟地址空间中的不同区域，映射到同一个物理页框上。这样，一个进程写入的数据，另一个进程可以立即看到。

内存映射文件：多个进程可以将同一个文件映射到自己的地址空间，从而实现基于文件的共享。这常用于共享库。

(COW)-写时复制：在fork()创建子进程时，父子进程最初共享所有物理页框（页表项标记为只读共享）。当任何一方尝试写入时，才为该进程复制私有副本。这实现了初始状态的高效共享。【belike：你可以在github上找喜欢的文章，但是想要修改需要复制一份用于自己改】

零页共享

置零页面（[[零页]]）

概念

这是物理内存中一个预先分配好的、内容全为零的物理页框。所有进程的逻辑零页在初始时都映射到这个相同的物理页框上。

使用环境

当操作系统加载一个程序或创建新进程时，它知道程序的某些部分（如未初始化的.bss段）在逻辑上应该是零。操作系统不会立即为这些全零的页面分配物理内存，而是将它们映射到一个特殊的、全局共享的零页。

地址意义

物理页框号（PFN）

例如32位地址：0x00401800，其中0x00401是其高20位，就是物理页框号，称为页号，用于定位第几页，找到是哪一个虚拟页，再通过页表查到物理页框。

页内偏移

上述32位地址中，0x800是其剩余的低12位，用于定位该0x00401页中的某具体字节。
因为一页 = 4KB = 4096 字节 = 2^12，所以需要 12 位来表示页内偏移，取值范围 0 ~ 4095。

映射基本解释

什么是映射

映射（mapping）是虚拟内存机制的核心操作，指在虚拟地址与物理资源之间建立一种对应关系。

类似在数学函数上的映射，每个y都有至少一个x与之对应（大概这个意思）。

你可以把映射想象成图书馆的索书号系统。一本《C程序设计语言》作为物理资源，它在图书馆书架上有一个物理位置——“三楼A区第2排第5格”。但读者不需要知道这个物理位置，只需要在目录系统中查到索书号“TP312C/123”。映射就是那张对照表：”TP312C/123 → 《C程序设计语言》”。至于该书的位置，当你需要时，询问图书管理员，它会告诉你。读者只管用索书号，图书管理员负责维护对照表、分配书籍的位置，处理书籍的调入调出。我们谈”映射”时，虚拟地址就是索书号，物理资源就是这本书，物理地址就是书架的实际位置，操作系统就是那个图书管理员。

为什么需要映射

隔离：每个读者（进程）有自己的”目录册”（虚拟地址空间），即使两本书的索书号相同，它们对应的物理位置可以不同。进程A的 0x00400000 和进程B的 0x00400000 映射到完全不同的物理页——互相看不见、改不了。

简化：读者不需要关心书在哪，就像程序不需要关心物理内存的碎片化——哪怕物理内存被切成了一百个小碎块，进程看到的始终是一块连续的、从零开始的虚拟地址空间。（上述的虚拟地址空间特性）

延迟：图书馆可以先在目录里登记书的信息，等读者真的来借了——如果书还没从仓库调过来，管理员立刻去调，读者等待片刻即可。这就是缺页异常和延迟分配的本质。

映射分层分为VMA层和页表（VMA上有详解，页表见《页的概念》）

映射分层

由于在程序运行的整个过程中经历了多次映射，即映射的层次划分较多，此处仅详细解释两个层次的映射，为方便理解后续的匿名和文件映射，详细映射内容另起一文总述。

区域级：VMA映射

VMA映射是第四层的映射关系，这一层是内核 execve() 或 mmap 系统调用后，在进程的 mm_struct 里建立的运行时数据结构。

映射关系：

虚拟地址区间 ↔ 后备存储（文件 或 匿名/零）

即它建立的是”虚拟地址区间 ↔ 数据来源“的对应关系，而不是“虚拟地址 ↔ 物理内存”。数据来源可以是：

​ 一个文件（vm_file 指向 inode）——文件映射

​ 没有信息，”无”，即全零（vm_file = NULL）——匿名映射

​ 两者独立不可转换

物理内存在这一层完全不出现。 mmap 返回时，VMA 已建立，但 RSS = 0，物理页为零。

比方为在图书馆中使用索书号TP312C/123（虚拟地址）能根据”VMA映射“这个列表，查到这本书名为《C程序设计语言》（对应的数据来源），至于书的位置，那是页表映射的工作。

逐页级：页表映射

这一层才是之前常说的的”虚拟内存 ↔ 物理内存”的关联，告诉你索书号对应的书在哪个具体位置（物理内存地址），但它是逐页、按需、延迟建立的。

想前面说的，VMA只是规划空间的用处，真正的分配则是页表的工作。

一个页表条目（PTE）记录的是最精确的映射（见《页的概念》）

匿名映射

分配空白页，比如创建一个空字符数组，其内容为空，创建时在磁盘上无占用，没有物理页。使用时即“凭空给一块0初始化的内存”。

类似我让他人预留了一张白纸（预留，所以无物理页存在，“白纸”意为着无内容），在管理员那里，写着windfire↔ 白纸（NULL，匿名映射），现在我需要拿到这张白纸写个“A”，于是管理员就给了我一张白纸，我再写，（缺页分配、按需分配）。

文件映射

就是关联了磁盘文件的虚拟地址，创建时在本身磁盘上无占用，但是关联的文件在磁盘上存在，注意，磁盘上的文件并不是该虚拟地址的映射位置。使用时分配物理页，并复制磁盘上对应的文件内容到该新物理页。

对data段等机制的进一步解释

以data段和bss段为例，由于突出data与bss的区别，在《分段》中写到，data是在运行时直接分配所有有数据的物理页，但实际上，data是私有文件映射的一种，也遵循按需分配和写时复制的规律，即调用前是没有物理页分配的，有需求时才即时分配。

但页表中，对应这 1MB 范围的全部 256 个 PTE（1MB / 4KB = 256 页），P 位全部为 0。

此时 ptr 是一个合法的虚拟地址指针——可以赋值、比较、作为参数传递。但它指向的 256 个虚拟页，没有一个真正对应物理内存。内核为这段映射消耗的物理内存，仅仅是 VMA 节点本身（约 100 多字节）以及多级页表中可能新建的中间级页表页。

阶段二

第一次写入第 0 页

((char*)ptr)[0] = 'A'; 这条 C 语句在 CPU 层面是一条 mov 指令。

CPU 发出写操作，MMU 查页表：

  1. 虚拟地址 0x7F1234000000 → 四级页表遍历。
  2. 在某一级遇到 P 位为 0 的条目 → 缺页异常（page fault）。
  3. CPU 切换到内核态，执行缺页异常处理程序。
  4. 内核在 VMA 树中查找 0x7F1234000000 → 命中刚才那个匿名私有 VMA。
  5. 检查访问类型（写操作 vs VMA 的 VM_WRITE）→ 合法。
  6. VMA 的 vm_file == NULL（匿名映射）→ 分配一个空闲物理页（如物理地址 0x2A3B1000）。
  7. 将该物理页全部填零（安全原因：不能泄漏前一个进程的残留数据）。
  8. 填充该虚拟页的 PTE：物理页框号 = 0x2A3B1（右移 12 位），P=1，R/W=1，NX=1（不可执行）。
  9. 返回用户态，CPU 重新执行那条 mov 指令 → MMU 再次查页表 → P=1 → 翻译成功 → 写入 0x2A3B1000。

此时进程的物理内存消耗增加了 4KB（一个物理页）。检查 /proc//smaps：

阶段三

写入第 511 个页

((char*)ptr)[510 * 4096] = 'Z'; 访问的是虚拟地址 0x7F1234000000 + 510 × 4096 = 0x7F123407F800，位于这 1MB 中的第 510 个页（从 0 计数的话）。

过程与阶段二完全相同——独立的缺页异常，独立分配另一个物理页，独立填充另一个 PTE。RSS 增加到 8KB。

关键观察：1MB 的 VMA 覆盖 256 个虚拟页，但现在只有第 0 页和第 510 页有物理内存。第 1509 页、第 511255 页仍然是 VMA 登记好、页表为空的”空地”。从 1MB VMA 的视角看，物理页是稀疏分布的——这就是”映射不是一次性完成”的直观体现。

RSS = 8KB，VMA 范围 = 1MB。

阶段四

munmap

munmap(ptr, 1024 * 1024); 做的是阶段一的反操作——逐一撤销。

  1. 内核在 VMA 树中找到覆盖 [0x7F1234000000, 0x7F1234100000) 的 VMA，删除或缩小它。
  2. 遍历该范围内所有 PTE——找到 P 位为 1 的条目（第 0 页和第 510 页），将对应的物理页归还给空闲物理页池。
  3. 清空所有相关 PTE（P 位置 0）。
  4. RSS 回到 0。VMA 移除。

整个过程下来，内核始终精确地追踪”谁（哪个 VMA）拥有这页”以及”这页的物理内存在哪”。VMA 和页表从未脱节——修改必然是同步的。

特定名词解释

内核态

内核态是操作系统的一种运行模式，具有对系统硬件和资源的完全访问权限，主要用于执行特权操作和管理系统资源。

深入解释涉及内核知识，此处不作深入说明。

显式内存

显式内存共享是操作系统提供的一种高级进程间通信机制。它允许两个或多个独立的进程，通过主动调用系统API，将各自虚拟地址空间中的一块区域，映射到同一块物理内存上。这样，一个进程写入这块内存的数据，另一个进程可以立即看到，从而实现高效、直接的数据交换。
