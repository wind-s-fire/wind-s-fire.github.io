变量定义相关

Global Variable

代码示例

作用域

作用域：从定义处开始到文件末尾的整个源文件。通过 extern 声明，可以被其他源文件访问（默认具有外部链接属性）。

生命周期

生命周期与整个程序的运行周期一致——程序启动时分配内存并初始化，程序结束时销毁。

位置

存放在静态存储区（数据段中的 .data 或 .bss 段）。

初始化

若未显式初始化，编译器自动将其初始化为零值（整数为 0，指针为 NULL）。

静态变量

Static Variable

static 关键字在不同上下文中有不同含义，但用 static 修饰的变量统称为静态变量，按出现位置分为两类：

静态全局变量

在全局作用域中用 static 修饰的变量。它与普通全局变量的区别在于链接属性被限制为内部链接——只能被当前源文件访问，其他文件即使使用 extern 也无法引用。

静态局部变量

作用域

在函数内部用 static 修饰的变量。它的核心特征是生命周期为整个程序运行期，但作用域仅限于定义它的函数内部。

生命周期

生命周期为整个程序运行期

因为静态局部变量存放在bss段中，bss段存在于整个程序的生命周期，所以静态变量，即使是局部静态变量的生命周期也是整个程序运行期。

静态局部变量的作用域限制纯粹是编译期的语法规则，而它的内存从程序启动到结束一直有效且地址固定。只要你拿到了它的指针，就可以在任意位置、任意函数中读写它，没有任何运行时屏障。

局部的类静态变量在类的所有实例之间共享，所有对象都可以访问同一个静态变量的值(文后有C语言和Python的代码详解类和实例)。

非作用域可调用原因

—编译器不允许你在函数外部直接写 count 这个标识符。但一旦拿到了指向这块内存的指针（或地址），CPU 执行访存指令时只看地址，根本不关心这个地址原本对应什么作用域的变量。内存控制器的视角里，所有的 RAM 地址都是平等的。

所以实际上，只要满足两个条件就可以从外部访问：

  1. 指针必须来自函数内部（通过返回值、输出参数、全局指针中转等方式泄露出去）
  2. 访问时机在变量生命周期内（静态局部变量的生命周期是程序全程，这个条件天然满足）

？C++ 中的特殊情况

C++11 起，标准明确要求静态局部变量的初始化是线程安全的。多线程环境下，如果多个线程同时首次进入该函数，编译器会插入额外的同步机制（如互斥锁或双重检查锁定），确保初始化只执行一次，其他线程要么等待，要么直接跳过。这进一步说明——后续调用就是纯粹的条件判断 + 跳过，逻辑上不触碰赋值语句。

特点

即静态局部变量在函数第一次被调用时初始化，之后每次调用函数时，它保留上一次的值，不会重新初始化。

第二次及之后调用函数、再次执行到 static int count = 0; 这一行时，编译器生成的底层代码会直接跳过初始化语句，连”尝试”的过程都没有。

编译器在编译阶段，会为每个静态局部变量悄悄生成一个隐藏的标志位（guard variable），用于追踪该变量是否已经被初始化过。实际运行的逻辑等价于：

特点

static 对全局变量的作用不是改变生命周期，而是改变可见性。 全局变量本身就已经有静态存储期，static 在这里的唯一作用是**将链接属性从”外部”降为”内部”**，实现文件级别的封装——类似于面向对象中的 private 成员，避免不同文件间的命名冲突。

静态局部变量 vs 普通局部变量：普通局部变量（自动变量）存放在栈上，函数返回后即销毁；静态局部变量存放在静态存储区，函数返回后值仍然保留，只是无法通过变量名直接访问（作用域限制）。

存放

所有全局变量和静态变量都位于进程的静态数据区，其中又分为：

  • .data 段：存放已初始化的变量（如 int x = 5）
  • .bss 段：存放未初始化或初始化为零的变量（如 static int y;）

这种统一的内存布局解释了为什么它们共享相同的生命周期——都在程序加载时分配，程序退出时释放。

类和实例

类是什么

类是描述一类事物的抽象模板，定义了这类事物”有什么属性”和”能做什么行为”，但它本身不是一个具体存在的东西。

比如”人类”就是一个类——它描述了人有姓名、年龄等属性，会吃饭、走路等行为。但你不能指着空气说”这是人类”，因为”人类”只是个概念框架。

实例是什么

实例是按照类这个模板创建出来的具体对象。类只是一个设计图纸，实例是根据图纸真正建造出来的那个东西。

张三、李四、王五就是”人类”这个类的三个实例——他们各自有自己独立的姓名和年龄，是三个活生生的、不同的个体。

用生活中的比喻来理解：

类 = 饼干模具，实例 = 用模具压出来的饼干。

模具（类）只有一个，它定义了饼干的形状。但你用同一套模具可以压出很多块饼干（实例），每块饼干虽然形状相同，却各自独立存在——你咬一口第一块，第二块并不会跟着少一块。

静态变量共享

即类中定义一个静态局部变量，每个实例都可以调用该变量，但是与实例变量不同，比如修改了实例-张三的身高，李四的身高数据不变，张三的成绩也不变，但是如果通过实例-张三修改学校总人数（静态局部类变量，不单独属于任何一个实例），之后从李四调用总人数也发生了改变。

总结

类（class Student:）** 就是一个蓝图。你在白纸上画好了一个学生的结构——有姓名、年龄、分数，还有一个全校通用的计数器。画完这张图不等于有了一个学生，你得照着它”制造”才出实例。

实例（zhangsan、lisi、wangwu） 是三个活生生的对象。它们各自拿着自己的 name、age、score，张三的分数改了，李四毫无感觉——就像三个人各自钱包里的钱，互不联通。

类变量（total_students） 不属于任何一个实例。从 __dict__ 的输出可以看到，张三的字典里只有 name、age、score，根本没有 total_students。这份数据只存在 Student.__dict__ 里，所有实例访问它时，实际上都是顺着类的线索找到同一块数据，改一处而动全身。

此处C与Python关键差异

C 语言中结构体只是纯数据的容器，行为和函数是分离的。Python 的 class 则将数据（变量） 和行为（方法） 打包在一起，self 参数让每个方法天然知道”是谁在调用自己”，代码组织更紧凑，读起来也更接近人类思维。
